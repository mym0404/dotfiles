# Deslop

사용자가 이 스킬을 명시적으로 호출한 작업에서만 서브에이전트를 사용하고, 그 작업 이후의 추가 작업에서는 다시 명시적으로 호출하지 않는 한 서브에이전트를 사용하지 않는다.

코드 판단과 수정은 [code-code](../code-code/SKILL.md)를 따른다. 시작할 때 전문을 읽고 적용한다. 이 스킬은 검토 범위와 세 검토자의 협업 절차를 정한다.

## 1. 범위와 맥락을 확정한다

- 사용자가 지정한 범위를 우선하고, 지정이 없으면 현재 세션의 최근 작업 맥락으로 정한다. 이번 세션에서 작업하지 않은 부분은 사용자가 해당 부분이나 전체 범위를 명시적으로 요청한 경우에만 포함한다. Git 변경 목록은 보조 근거로만 쓴다.
- 대상 파일과 수정에 필요한 호출부를 확인하고, `code-code`의 `Program Context`에 따라 공통 맥락을 파악한다. 결과를 바꾸는 미결정 사항은 `Decision Gate`로 해결한다.
- 확정한 범위의 안티패턴을 모두 수정한다. 변경량에 상한을 두지 않는다.

완료 조건: 검토 대상 파일, 필요한 호출부, 공통 맥락과 보존할 동작을 확정했다.

## 2. 세 검토자에게 독립 검토를 맡긴다

정확히 세 subagent를 병렬로 실행한다. 같은 코드 상태, 공통 맥락, 확정한 범위, `code-code` 전문을 전달하고 다음 관점을 맡긴다.

| 검토자 | 관점 | 집중해서 적용할 `code-code` 규칙 |
|---|---|---|
| 맥락과 방어 | 현재 제약에 필요한 방어와 작업 생명주기 | `Program Context`, `Boundary`, `Necessary Defenses` |
| 단순성과 책임 | 표현, 책임 배치, 추상화와 제어 흐름 | `Direct Ownership`, `Readability`, `Function Patterns`, `Comments` |
| 재사용과 계약 | 기존 구현 활용, 타입과 모듈, 외부 동작 보존 | `Reuse Before Implementation`, `Type Design`, `Type Safety`, `Module Boundaries`, `Boundary` |

각 위임에 다음 실행 계약을 명시한다.

- 범위: 확정한 파일과 관점을 검토하고, 검증에 필요한 사용처를 조사한다.
- 편집 가능한 파일: 없다. 파일 수정, VCS 변경, 외부 쓰기를 금지한다.
- 기대 출력: 검사한 파일 목록과 발견별 위치·근거·수정안·검증 방법을 보고한다. 확인하지 못한 파일과 가정도 명시한다.
- 검증 책임: 실제 요구사항, 사용처와 `code-code` 규칙으로 문제를 입증한다. 필요한 코드라고 판단하면 유지 근거를 제시한다.

완료 조건: 세 보고서를 받았고, 각 검토자가 대상 파일을 모두 확인했거나 미확인 부분을 명시했다.

## 3. 주 에이전트가 판단하고 수정한다

- 중복 발견을 합치고, 발견별로 `수정`, `기각`, `범위 밖`, `차단` 중 처리 결과와 근거를 기록한다. 의견이 충돌하면 실제 코드와 요구사항으로 판단한다.
- 주 에이전트가 범위 안에서 채택한 문제를 모두 수정한다. `code-code`의 범위·동작 보존·삭제 규칙을 적용한다.
- 결과를 바꾸는 사용자 결정이 필요하면 해당 항목을 차단으로 남기고, 그 결정에 의존하지 않는 수정은 계속한다.

완료 조건: 모든 발견에 처리 결과를 기록했고, 채택한 수정을 코드에 반영했다.

## 4. 검증하고 같은 세 검토자에게 재검토를 맡긴다

- `code-code`의 `Verification Loop`로 변경을 검증한다. 기존 검사와 테스트를 쓰고 새 테스트는 추가하지 않는다. 변경 범위 밖의 기존 오류는 따로 보고한다.
- 같은 세 검토자에게 최신 코드, 수정 내역, 발견별 처리 결과와 기존 검사 결과를 전달한다.
- 각 검토자가 자신의 관점에서 최신 코드와 검사 결과를 직접 확인한다. 기존 지적의 해결 여부와 변경 코드·영향받는 호출부의 새 문제 또는 동작 변경을 검토한다.
- 근거 있는 미해결 문제가 남으면 3–4단계를 반복한다. 반복 중에도 확정한 범위를 유지한다.

완료 조건: 세 관점 모두 미검토 파일과 근거 있는 미해결 문제가 없고, 채택한 수정의 검증 기준과 필요한 기존 검사를 모두 통과했다.

세 검토자를 실행할 수 없거나 사용자 결정·검증 차단이 남으면 미완료로 보고한다. 최종 보고에는 수정 내용, 기각 근거, 검증 결과와 남은 차단을 포함한다.
