# Deslop

코드 판단과 수정 규칙은 [code-code](../code-code/SKILL.md)를 기준으로 삼아요. 시작할 때 전문을 읽고 적용해요. 이 스킬은 검토 범위와 세 검토자의 협업 절차를 정해요.

## 1. 범위와 맥락을 확정해요

- 사용자가 지정한 대상이 있으면 따르고, 없으면 대화에서 최근 작업한 부분이나 마지막 명령이 다루는 코드를 찾아요. Git 변경 목록은 이를 확인하는 보조 근거로 사용해요.
- 대상 파일과 수정에 필요한 호출부를 확인하고, `code-code`의 `Program Context`에 따라 공통 맥락을 파악해요. 결과를 바꾸는 미결정 사항은 `Decision Gate`로 해결해요.
- 확정한 범위 안의 안티패턴을 모두 수정하는 것을 목표로 삼아요. 변경량에는 상한을 두지 않아요.

완료 조건: 검토 대상 파일, 필요한 호출부, 공통 맥락과 보존할 동작이 정해져 있어요.

## 2. 세 검토자에게 독립 검토를 맡겨요

정확히 세 subagent를 병렬로 실행해요. 모두 같은 코드 상태와 공통 맥락, 확정한 범위, `code-code` 전문을 받으며 다음 관점에 집중해요.

| 검토자 | 관점 | 집중해서 적용할 `code-code` 규칙 |
|---|---|---|
| 맥락과 방어 | 현재 제약에 필요한 방어와 작업 생명주기 | `Program Context`, `Boundary`, `Necessary Defenses` |
| 단순성과 책임 | 표현, 책임 배치, 추상화와 제어 흐름 | `Direct Ownership`, `Readability`, `Function Patterns`, `Comments` |
| 재사용과 계약 | 기존 구현 활용, 타입과 모듈, 외부 동작 보존 | `Reuse Before Implementation`, `Type Design`, `Type Safety`, `Module Boundaries`, `Boundary` |

각 위임에 다음 실행 계약을 명시해요.

- 범위: 확정한 파일과 관점, 검증에 필요한 사용처 조사예요.
- 편집 가능한 파일: 없어요. 파일 수정, VCS 변경, 외부 쓰기를 허용하지 않아요.
- 기대 출력: 검사한 파일 목록과 각 발견의 위치·근거·수정안·검증 방법이에요. 확인하지 못한 파일이나 가정도 명시해요.
- 검증 책임: 실제 요구사항, 사용처와 `code-code` 규칙으로 문제를 입증하고, 필요한 코드로 판단했다면 유지 근거를 제시해요.

완료 조건: 세 보고서가 도착하고, 각 관점에서 대상 파일을 모두 확인했거나 확인하지 못한 부분을 명시했어요.

## 3. 주 에이전트가 판단하고 수정해요

- 중복된 발견을 합치고, 각 발견에 `수정`, `기각`, `범위 밖`, `차단` 중 처리 결과와 근거를 연결해요. 의견이 충돌하면 실제 코드와 요구사항으로 판단해요.
- 채택한 범위 안의 문제를 주 에이전트가 모두 수정해요. 코드 변경은 `code-code`의 범위·동작 보존·삭제 규칙을 적용해요.
- 결과를 바꾸는 사용자 결정이 필요하면 해당 항목을 차단으로 남기고, 그 결정에 의존하지 않는 수정은 계속해요.

완료 조건: 모든 발견에 처리 결과가 있고, 채택한 수정이 코드에 반영되어 있어요.

## 4. 검증하고 같은 세 검토자에게 재검토를 맡겨요

- `code-code`의 `Verification Loop`로 변경을 검증해요. 기존 검사와 테스트를 사용하고 새 테스트는 추가하지 않아요. 변경 범위 밖의 기존 오류는 따로 보고해요.
- 같은 세 검토자에게 갱신한 코드, 수정 내역, 발견별 처리 결과와 기존 검사 결과를 전달해요.
- 각자 자신의 관점에서 최신 코드와 검사 결과를 직접 확인해요. 재검토는 기존 지적의 해결 여부와 변경한 코드·영향받는 호출부의 새 문제 또는 동작 변경에 집중해요.
- 근거 있는 미해결 문제가 남으면 3–4단계를 반복해요. 반복 중에도 확정한 범위를 유지해요.

완료 조건: 세 관점 모두에 미검토 파일과 근거 있는 미해결 문제가 없고, 채택한 수정의 검증 기준과 필요한 기존 검사가 모두 통과했어요.

세 검토자를 실행할 수 없거나 사용자 결정·검증 차단이 남으면 미완료로 보고해요. 최종 보고에는 수정한 내용, 기각 근거, 검증 결과와 남은 차단을 포함해요.
