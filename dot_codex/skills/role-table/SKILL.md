# Role Table

질문이 비교하려는 책임의 경계를 보여준다. 책임 주체는 미리 정해진 종류가 아니라 질문이 묻는 수준에서 결정한다.

## 작성 순서

1. 질문의 비교 대상과 핵심 동사를 보고 어떤 수준의 책임을 묻는지 정한다. 작업을 실행·판단·승인하는 주체를 묻는지, 기능을 제공하거나 규칙을 정의하는 주체를 묻는지 구분한다. 질문에 명시된 비교 기준을 우선한다.
2. 관련 코드·문서를 확인하고 그 수준에서 실제로 책임지는 주체와 역할을 구분한다. 기술 구성요소를 비교할 때는 기본 기능을 제공하는 구성요소와 이를 이용해 규칙·조합을 구현하는 구성요소를 나눈다. 확인하지 못한 책임은 추측으로 채우지 않고 `미확인`으로 표시한다.
3. 아래 형식으로 정리한다. 첫 열이 질문의 비교 기준과 같은 수준인지, 도구·명령·작업 대상을 실제 책임 주체로 혼동하지 않았는지, 주요 역할과 링크가 확인한 근거에 맞는지 검토한다.

## 출력 형식

표는 다음 3열로 고정한다.

| 책임 주체 | 역할 | 설명 |
|---|---|---|

- **책임 주체:** 질문에서 정한 수준의 실제 주체를 쓴다. 기술 구성요소가 주체라면 소속 Provider와 세부 구성요소가 이름에 드러나게 쓴다. 주체를 확인할 수 없으면 `책임 주체 미확인`으로 표시한다.
- **역할:** `파일 읽기`, `JSON 해석`, `설정 규칙 정의`처럼 맡은 일을 짧게 쓴다.
- **설명:** 주체가 그 역할을 어떻게 맡는지 한 문장으로 설명한다. 다른 구성 위에 만들어졌다면 그 기반을 함께 밝힌다.
- 직접 만든 유틸리티·스키마·컴포넌트 등의 위치는 설명 안에 Markdown 링크로 붙인다. 로컬 파일은 확인한 절대 경로를, 외부 문서나 디자인 요소는 확인한 URL을 사용한다. 위치를 확인하지 못했다면 링크 대신 `위치 미확인`으로 표시한다.
- 한 행에는 하나의 역할을 둔다. 같은 책임 주체가 여러 역할을 맡으면 행을 나눈다.
- 동작 순서나 기반 기능에서 조합된 기능 순으로 행을 배치한다. 표만으로 설명되면 서론과 요약을 덧붙이지 않는다.
