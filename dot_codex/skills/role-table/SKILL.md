# Role Table

구성을 이루는 모듈 사이의 책임 경계를 보여준다. 책임은 기능을 실행하거나 규칙을 정의하는 기술적 구성요소를 뜻하며, 사람·팀의 담당 업무나 조직 소유권은 다루지 않는다.

## 작성 순서

1. 질문에 해당하는 코드·문서를 확인하고, 동작을 이해하는 데 필요한 구성과 연결을 파악한다. 확인하지 못한 책임은 추측으로 채우지 않고 `미확인`으로 표시한다.
2. 기본 기능을 제공하는 모듈과 그 기능을 이용해 규칙·조합을 구현한 모듈을 나눈다. 예를 들어 라이브러리의 값 검증과 우리 코드의 스키마 정의는 별도 책임이다. 관련된 각 역할을 담당하는 모듈이 구분되면 표를 작성한다.
3. 아래 형식으로 정리하고, 책임 주체 이름만으로 Provider를 알 수 있는지, 질문의 주요 역할이 빠짐없이 들어갔는지, 링크가 확인한 위치를 가리키는지 검토한다.

## 출력 형식

표는 다음 3열로 고정한다.

| 책임 주체 | 역할 | 설명 |
|---|---|---|

- **책임 주체:** 기능이나 규칙을 제공하는 시스템·제품·라이브러리·프로젝트인 Provider와 세부 구성요소가 드러나도록 이름을 쓴다. `Contract`, `Figma Binding`, `설정 스키마`처럼 소속을 알 수 없는 이름만 쓰지 않고 `Rosetta 내 Contract`, `Rosetta 내 Figma Binding`, `<프로젝트명> 내 설정 스키마`처럼 표기한다. `Figma`, `Figma Code Connect CLI`처럼 이름 자체로 Provider가 명확하면 그대로 쓴다. Provider는 설명이나 링크에만 두지 않고 책임 주체 열에 명시하며, `우리 코드`나 사람·팀 이름으로 대신하지 않는다. 확인할 수 없으면 `Provider 미확인 — <구성요소명>`으로 표시한다.
- **역할:** `파일 읽기`, `JSON 해석`, `설정 규칙 정의`처럼 맡은 일을 짧게 쓴다.
- **설명:** 기본으로 제공되는 기능인지, 우리가 무엇을 이용해 무엇을 만든 것인지 한 문장으로 설명한다. 다른 구성 위에 만들어졌다면 그 기반을 함께 밝힌다.
- 직접 만든 유틸리티·스키마·컴포넌트 등의 위치는 설명 안에 Markdown 링크로 붙인다. 로컬 파일은 확인한 절대 경로를, 외부 문서나 디자인 요소는 확인한 URL을 사용한다. 위치를 확인하지 못했다면 링크 대신 `위치 미확인`으로 표시한다.
- 한 행에는 하나의 역할을 둔다. 같은 책임 주체가 여러 역할을 맡으면 행을 나눈다.
- 동작 순서나 기반 기능에서 조합된 기능 순으로 행을 배치한다. 표만으로 설명되면 서론과 요약을 덧붙이지 않는다.
