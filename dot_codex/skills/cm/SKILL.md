# Commit All Changes

Use the entire current repository as the scope, including changes from earlier tasks. Choose commit boundaries autonomously on the current branch, without pushing. Preserve file contents and existing history; commit changes rather than discarding, stashing, or hiding them to obtain a clean status.

1. Inspect `git status --short --untracked-files=all`, `git diff`, and `git diff --cached` from the repository root, and read every untracked file. Inspection is complete when every staged, unstaged, and untracked change is understood. Honor existing ignore rules; ignored files are outside this scope unless explicitly requested. If status is already empty, report that there is nothing to commit.
2. Account for every status entry and hunk, including changes outside the current conversation. Resolve scope from the actual changes rather than the latest task. If an entry cannot be committed safely, report its exact path and reason as a blocker, not as successful completion.
3. Group changes into atomic commits: one independently reviewable purpose per group. Separate distinct features, fixes, and independent refactors; keep an implementation with its required tests, documentation, and dependency changes. Use intent and functional dependencies rather than file type or size. Order prerequisites first so each commit is coherent at that point in history. Keep one commit when all changes have only one cohesive purpose. Grouping is complete when every changed hunk and untracked file belongs to exactly one group; briefly state the groups and proceed without asking the user to choose boundaries.
4. For each group consisting of whole files, run `git add -- <group-paths>`, review `git diff --cached -- <group-paths>`, and run `git diff --cached --check -- <group-paths>`. Create a concise English Conventional Commit with `git commit --only -m "<message>" -- <group-paths>`. If a file spans groups, use hunk-level staging in an isolated temporary index initialized from `HEAD`, review its entire staged diff, and commit that index without `--only`; `--only` would include the file's remaining working-tree changes. Preserve the working tree and staged changes assigned to other groups, reconcile committed target entries in the original index, and remove the temporary index after use. Each group is complete when the resulting commit diff contains exactly its assigned changes.
5. Verify all created commits against the groups and rerun `git status --short --untracked-files=all` from the repository root without a path filter. If hooks or commits leave further changes, inspect and group them through the same workflow. Successful completion requires empty status: no staged, unstaged, or untracked changes remain. Report each commit hash and message and the clean status. If a commit fails or changes cannot be committed, stop and report completed commits plus every remaining path and blocker; do not claim completion.
