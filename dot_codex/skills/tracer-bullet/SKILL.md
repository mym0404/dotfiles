# Tracer Bullet

**원하는 기능을 가장 작은 실제 경로로 실행해서, 되는지 빠르게 확인해요.** 만든 코드는 제품에 그대로 이어 쓸 수 있게 남겨요.

사용자의 요청을 “이 입력을 넣으면 이 결과가 나온다” 한 문장으로 정하고 바로 검증에 필요한 코드를 확인해요. 기존 구조를 재사용해 입력부터 결과까지 연결하고 실행해요. 여러 기능이 있으면 성립 여부가 가장 불확실한 핵심 기능부터 확인해요.

## 실행 기준

- 첫 실행에 필요한 코드만 만들어요. 화면 꾸미기, 부가 기능, 범용 구조는 결과를 확인한 뒤 요청 범위에 맞춰 다뤄요.
- 기능이 의존하는 실제 연결을 통과시켜요. 저장 기능이면 저장 후 다시 읽고, 외부 연동이면 실제 응답을 확인해요. 프로젝트에 없는 계층을 검증용으로 새로 만들 필요는 없어요.
- 기능의 폭을 줄여도 선택한 경로의 필수 오류 처리·입력 검사·권한 검사는 유지해요. 코드는 기존 제품 구조에 연결해요.
- 예상과 다르면 실행 증거로 원인을 좁히고, 요청 범위 안에서 최소한으로 수정한 뒤 같은 입력으로 다시 확인해요.
- 빌드나 mock 테스트 통과는 실제 기능의 성공과 구분해요. 환경·권한 때문에 실행하지 못한 부분은 미검증으로 남겨요.

## 끝내는 기준

요청한 결과를 실제로 확인하면 검증을 마쳐요. 해결에 사용자 결정이나 외부 조건이 필요하면 막힌 지점과 필요한 조건을 알려줘요. 검증만 요청했다면 여기서 끝내고, 전체 구현까지 요청했다면 확인한 코드를 바탕으로 남은 요청을 이어가요. 설명이나 계획만 요청했으면 코드를 변경하지 않아요.

결과는 **되는지, 무엇을 실행해 확인했는지, 남은 제약이 무엇인지** 짧게 알려줘요. 판정은 실제로 확인한 환경과 입력 범위에 한정해요.
