# Explain Diff Korean Hard Mode

이 파일은 Explain Diff의 한국어 교정과 검증을 위한 유일한 규칙이다. 항상 전체를 읽고 모든 규칙을 적용한다. 확실하게 고칠 수 있는 문제만 다루고, 문맥에 따라 뜻이 갈리면 원문을 유지한다.

## 적용 범위

- 제목, 요약, 본문, 도표, 콜아웃, 표, 목록, 레이블, 코드 블록 제목, 퀴즈 질문·선택지·피드백 등 사용자에게 보이는 모든 한국어를 문장별로 검사한다.
- 설명 문장은 간결하고 일관된 해요체로 쓴다. 짧은 제목과 레이블은 자연스러운 명사형을 쓸 수 있다.
- 코드 블록 안의 코드와 사용자에게 직접 인용한 문장은 교정하지 않는다.
- 완성 HTML에서는 텍스트 노드만 교정한다. HTML 태그·속성·`data-*` 값·CSS·JavaScript·코드·식별자·경로·URI·HTML escape는 바꾸지 않는다.
- 깨끗한 문장은 고치지 않는다. 다양성을 만들려고 종결, 시제, 어휘를 억지로 바꾸지 않는다.

## 보호 범위

- 사람·지역·기관·브랜드·제품·모델 이름을 보존한다.
- 수치·날짜·단위·금액을 보존한다.
- 직접 인용과 법령 조문을 보존한다.
- 코드·식별자·명령어·URL·Markdown 링크·영어 약어를 보존한다.
- 사실·주장·인과관계·결론·문장 수·순서를 보존한다.
- 헤딩·목록·표·코드 블록과 주변 파일 구조를 보존한다.
- 기술 문서에서는 공식 표기를 유지하고 같은 개념에 같은 용어를 쓴다.

## 맞춤법과 띄어쓰기

- 정답이 분명한 오타를 고친다: `됬다→됐다`, `몇일→며칠`, `역활→역할`, `오랫만→오랜만`, `희안하다→희한하다`, `금새→금세`, `왠만하다→웬만하다`.
- 받침이 없으면 `예요`, 받침이 있으면 `이에요`를 쓴다. `아니에요`는 그대로 쓴다.
- 약속 종결은 `-ㄹ게`, 의도는 `-려고`로 쓴다.
- `어떻게`와 `어떡해`, `율`과 `률`, `낫다`와 `낳다`처럼 답이 분명한 혼동을 고친다.
- 조사는 앞말에 붙이고 의존 명사 `것·수·데·지`는 띄운다.
- 수와 단위, 이름과 호칭은 띄어 쓴다: `한 개`, `두 살`, `홍길동 씨`.
- 금지·부정의 `안 되다`는 띄어 쓴다.
- 불필요한 접속사 뒤 쉼표와 중복 마침표를 정리한다.
- 브랜드나 서비스가 의도한 표기는 표준 표기와 달라도 유지한다.

## 문장

- 이중 피동을 단일 피동이나 능동으로 고친다: `판단되어진다→판단된다`, `보여지는→보이는`, `쓰여진→쓰인`.
- 피동형이 행위 주체를 가리면 원문에 드러난 주체를 살려 능동형으로 고친다. 주체가 없으면 새로 만들지 않는다.
- 군더더기 `있다`, `수 있는`, `것`, `적`, `의`, `들`은 빼도 뜻이 같을 때만 줄인다.
- 가벼운 동사를 구체 동사로 바꾼다: `회의를 가지다→회의를 열다`, `변경을 수행하다→변경하다`.
- 뜻이 분명하면 전치사 번역투를 자연스럽게 고친다: `계획에 대해 설명하다→계획을 설명하다`, `분석을 통해 확인하다→분석해 확인하다`.
- `에 있어`, `의 경우`, `로 인하여`, `와 관련하여`가 군더더기면 알맞은 조사나 어미로 줄인다.
- 불필요한 명사화를 동사로 바꾼다: `설정 변경을 진행한다→설정을 바꾼다`.
- 연결어미 뒤에 불필요하게 붙은 쉼표를 뺀다.
- 문장을 합치거나 나누지 않고 문장 안에서만 다듬는다.

## AI 문체

- 빈 도입을 바로 본론으로 고친다: `오늘날 빠르게 변화하는 시대에`, `바야흐로`, `이 글에서는 살펴본다`.
- 빈 맺음을 직접 서술로 고친다: `결론적으로`, `요약하면`, `시사하는 바가 크다`, `지금이야말로 ~할 때다`.
- 근거 없는 과장을 빼거나 원문에 있는 사실로만 바꾼다: `혁신적인`, `획기적인`, `압도적인`, `놀라운`, `매우 중요한`.
- 메타 멘트를 뺀다: `좋은 질문입니다`, `간단히 말하자면`, `다음과 같습니다`.
- 상투적인 강조 틀을 직접 서술로 바꾼다: `단순한 X가 아니라 Y`, `중요한 것은 X라는 점이다`.
- `또한`, `따라서`, `즉`이 없어도 흐름이 같으면 뺀다.
- `~라는 것이다`, `~라는 점이다`, `~라는 뜻이다`가 군더더기면 평서형으로 끝낸다.
- 막연한 출처를 사실처럼 바꾸지 않는다. 출처를 확인할 수 없으면 해당 주장을 유지한 채 표현만 보수적으로 다듬거나 원문을 둔다.
- 원문에 없는 수치·사례·감정·구어체를 만들어 자연스러움을 연출하지 않는다.

## 문체와 높임

- 설명 문장의 해요체를 유지하고 불필요한 혼용만 고친다.
- 반말과 존댓말을 섞지 않는다.
- 사물에 붙은 과잉 높임을 고친다: `커피 나오셨습니다→커피 나왔습니다`, `품절이십니다→품절입니다`.
- 사람을 높이는 간접높임과 객체높임은 유지한다: `말씀이 있으시다`, `선생님께 드리다`.
- 쉬운 말로 고치되 법률·계약·전문 용어는 유지한다.

## 문맥 의존 맞춤법

- `되/돼`, `안/않`, `-데/-대`, `-든/-던`, `로서/로써`, `채/체`, `맞히다/맞추다`는 문맥으로 판단한다.
- `부치다/붙이다`, `늘리다/늘이다`, `결제/결재`, `지양/지향`은 실제 뜻이 확실할 때만 고친다.
- 사이시옷, 두음법칙, 외래어 표기는 고유명사·전문어·브랜드 여부를 먼저 확인한다.
- 조사, 높임, 시제처럼 복수 해석이 가능한 표현은 한 가지 해석을 임의로 선택하지 않는다.

## 번역투와 문장 구조

- 무생물·추상 주어에 `보여 주다`, `말하다`, `가져오다`, `가능하게 하다`를 붙인 문장은 같은 문장 안에서 원인이나 실제 주체가 드러나게 고친다.
- `그·그녀·그것·그들`이 한 문단에 세 번 이상 나오면 뜻이 분명한 범위에서 생략하거나 원래 명사로 바꾼다.
- `에 의해` 피동, `로부터`, `에서의·에로의·으로의·에의` 같은 조사 결합은 문맥에 맞는 조사나 어미로 고친다.
- `가지고 있다`, `만들다`, `제공하다`, `수행하다`, `진행하다`, `실시하다`, `처리하다`가 실제 동작을 가리면 구체 동사로 바꾼다.
- `-고 있다`가 영어 진행형을 그대로 옮긴 표현이면 단순 시제로 고친다. 진행이나 결과 상태가 핵심이면 유지한다.
- 긴 관형구와 관계절은 문장 수를 바꾸지 않는 범위에서 핵심 명사가 빨리 드러나게 재배치한다.
- 영어 관사에서 온 `그`, `어떤`, `하나의`는 없어도 뜻이 같을 때만 뺀다.
- 영어 현재·과거·완료 시제를 기계적으로 옮긴 흔적을 고치되 사건 순서와 확실성은 바꾸지 않는다.

## 문서 전체 반복

- 같은 문두 접속사가 다섯 번 이상 나오면 꼭 필요한 것만 남긴다.
- `결론적으로·따라서·이를 통해·그러므로`가 합쳐서 세 번 넘게 나오면 인과 표시에 필요한 것만 남긴다.
- `것이다·점이다·뜻이다` 종결이 세 번 이상 나오면 직접 종결로 바꿀 수 있는 문장만 고친다.
- `할 수 있다`, `해야 한다`, `필요하다`, `것으로 보인다`가 네 번 이상 반복되면 가능성·의무·불확실성이 실제 의미인지 문장마다 확인한다.
- 같은 종결이 네 문장 이상 이어지면 문법적으로 자연스럽고 의미가 같은 범위에서만 조정한다. 시제·의무·확실성을 바꿔 변주하지 않는다.
- 같은 핵심 어휘가 한 문단에 세 번 이상 나오면 정확히 같은 뜻의 대체어가 있을 때만 일부를 바꾼다.
- `-성·-적·-화`와 `작업·수행·진행·실시`가 반복되면 동사로 풀 수 있는 표현만 고친다.
- 과장 어휘, 삼단 병렬, `X에서 Y로`, `A인가 B인가` 같은 상투적 틀이 세 번 이상 반복되면 핵심 한 번만 남긴다.
- 연결어미 뒤 쉼표가 반복되면 불필요한 쉼표를 모두 뺀다.

## 영어와 장르

- 한국어로 널리 쓰는 말이 있는데 영어 일반어를 반복하면 자연스러운 한국어로 바꾼다.
- API, SDK, LLM, GPU, 제품명, 표준 기술 용어는 유지한다.
- 괄호 속 영어 병기는 독자에게 필요한 첫 등장만 남기되 구조를 바꾸지 않는다.
- 기술 설명이라는 원래 장르를 유지한다.
- 사람 냄새를 내려고 구어체, 감탄, 개인 경험, 비유를 새로 넣지 않는다.

## 판단 기준

- 바꾼 뒤 뜻이 조금이라도 달라지면 원문으로 되돌린다.
- 잔존 문제나 보존 실패가 있을 때만 보수적으로 한 번 더 고친다.
- 다시 확인해도 의미 보존과 교정이 충돌하면 원문을 유지한다.

## 적용 절차

1. 대상에서 보호할 문자열과 구조를 먼저 확인한다.
2. 이 파일의 문장 규칙과 문맥 의존 규칙을 모든 사용자 노출 한국어에 문장별로 적용한다.
3. 문단과 문서 전체에서 반복되는 접속사, 종결, 완곡 표현, 명사화, 영어 표현을 확인한다.
4. 잔존 문제나 보존 실패가 있을 때만 해당 문장을 보수적으로 한 번 더 고친다.
5. `강한 검증`을 통과한 결과만 사용한다.

## 긴 일반 텍스트 초안

긴 `.txt` 또는 `.md` 초안을 파일로 만든 경우에만 OS 임시 디렉터리에서 다음 도구를 사용한다. 명령은 Explain Diff 스킬 디렉터리에서 실행한다.

```sh
python3 scripts/segment.py "$RUN_DIR/input.txt" --outdir "$RUN_DIR"
python3 scripts/reassemble.py "$RUN_DIR/segments.json" "$RUN_DIR/worksheet.md" --out "$RUN_DIR/result.txt"
```

- `worksheet.md`의 각 `윤문:` 줄에 한 문장만 채운다.
- 헤딩·목록·표·인용·코드 펜스처럼 스크립트가 구조로 보호한 사용자 노출 문구는 직접 검사한다.
- 종료 코드 `2`면 누락·추가된 문장을 고친 뒤 다시 실행한다.
- 변경률이 `30%`를 넘으면 더 보수적으로 고친 뒤 다시 실행한다.
- 종료 코드 `3`이면 결과를 사용하지 않는다.
- 검증을 마친 뒤 결과를 초안에 반영하고 임시 디렉터리를 삭제한다.
- 완성 HTML에는 이 도구를 실행하지 않는다.

## 강한 검증

1. 고유명사·수치·날짜·단위·금액·직접 인용이 그대로인지 확인한다.
2. 코드·식별자·URL·링크·법령·영어 약어가 그대로인지 확인한다.
3. 문장 수·순서·헤딩·목록·표·코드 블록과 HTML 구조가 그대로인지 확인한다.
4. 뜻·인과관계·확실성·의무·시제·결론이 그대로인지 확인한다.
5. 기술 설명 장르와 해요체가 유지되는지 확인한다.
6. 이 파일의 반복 기준에 해당하는 문제가 남았는지 확인한다.

위반이 있으면 해당 변경을 되돌리고 한 번만 다시 교정한다. 여섯 항목을 모두 통과한 결과만 사용한다.
