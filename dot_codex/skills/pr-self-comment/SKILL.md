# PR Self Comment

## 실행 범위

- 기본 동작은 대상 PR에 셀프리뷰를 등록하는 것이다. `초안만`을 요청하면 위치와 댓글 본문만 응답한다.
- 스킬을 만들거나 수정하는 요청은 PR에 댓글을 게시하라는 요청이 아니다.
- 코드, PR 본문, 브랜치, 커밋은 변경하지 않는다.

## 1. PR과 근거 확인

사용자가 지정한 PR을 사용한다. 지정하지 않았다면 현재 대화와 브랜치에서 PR을 찾고, 하나로 특정할 수 없을 때만 대상을 묻는다. URL 또는 Git remote에서 호스트를 확인하고 해당 호스트의 GitHub 도구나 `gh`를 사용한다.

PR 본문, 최신 head SHA, 전체 diff, 기존 일반 댓글과 인라인 리뷰를 읽는다. 설명할 변경의 주변 코드와 호출부를 따라가 역할, 변경 이유, 경계 조건을 확인한다. 이유가 불분명하면 관련 커밋과 이력을 확인한다.

완료 기준: 전체 변경 파일을 확인했고, 설명이 필요한 부분과 이미 설명된 부분을 구분했으며, 각 댓글의 근거와 게시 위치를 정했다.

## 2. 셀프리뷰 작성

### 파일별 인라인 댓글

- 핵심 구현이나 설명이 필요한 변경에 댓글을 단다. 단순 이름 변경, 생성 파일, 반복되는 변경까지 파일 수에 맞춰 채우지 않는다.
- 짧은 불릿으로 역할과 처리 흐름을 설명한다. 변경 이유, 예외 처리, 다른 코드와의 관계는 이해에 필요한 것만 덧붙인다.
- 기본 말투는 "다체" `했습니다.` `입니다.` 다. 식별자는 백틱으로 감싸고, 코드에 보이는 문장을 그대로 풀어 쓰는 설명은 줄인다.
- 한 댓글은 보통 불릿 2~4개로 쓴다. 간단한 변경은 한 문장으로 끝내고, 모든 댓글에 같은 틀을 강제하지 않는다.
- 최신 diff에서 확인한 파일과 줄에 연결한다. 적절한 줄이 없으면 파일 댓글이나 요약 댓글로 설명한다.

예시:

> - DOM 요소 하나의 눌림 애니메이션을 재생하고 멈추는 클래스입니다.
> - 누르던 중 손을 떼거나 다시 누르면 현재 크기에서 이어 재생하도록 했습니다.
> - `dispose()`에서 애니메이션과 예약한 프레임을 정리합니다.

### PR 요약 댓글

파일별 설명을 반복하지 않고, 변경 전반에서 알아둘 점과 확인한 내용, 리뷰어에게 확인받고 싶은 부분을 짧은 불릿으로 남긴다. 추가로 전달할 내용이 없으면 생략한다.

검증 결과는 실행 기록이나 사용자가 제공한 사실에 근거해 범위를 밝혀 쓴다. 코드상 정리 로직을 읽은 것과 실제 메모리 누수를 측정한 것은 구분한다. 개인적 감상, 직접 체험, 향후 작업 약속은 사용자가 제공한 경우에만 반영한다. 자연스럽게 보이려고 말줄임표나 오타를 만들지 않는다.

완료 기준: 모든 주장에 근거가 있고, 기존 댓글·PR 본문과 중복되는 설명을 줄였으며, 각 댓글이 해당 코드를 이해하는 데 도움이 된다.

## 3. 등록과 확인

초안만 요청했다면 여기서 위치와 본문을 응답하고 끝낸다. 기본 실행에서는 완성한 댓글을 대상 PR에 등록한다.

- 게시 직전에 head SHA와 기존 댓글을 다시 확인한다. head가 바뀌면 영향받는 설명과 줄 번호를 다시 맞춘다.
- 동일한 내용이 이미 있으면 건너뛴다. 기존 댓글 수정은 사용자가 요청한 본인 댓글에 한정한다.
- 인라인 댓글은 가능하면 `COMMENT` 리뷰 하나로 제출하고, 전체 요약은 일반 PR 댓글로 남긴다. 기존 미제출 리뷰는 그대로 둔다.
- 본문은 구조화된 도구 인자나 임시 JSON·본문 파일로 전달해 줄바꿈과 백틱을 보존한다.
- 등록 결과가 불확실하면 원격 댓글을 조회한 뒤 누락된 것만 처리한다. 실패 원인을 해결할 수 없으면 성공한 범위와 남은 댓글을 알리고 멈춘다.

완료 기준: 원격에서 댓글의 본문과 위치를 확인했고, 중복 게시가 없으며, 이번 실행에서 만든 임시 파일을 삭제했다. 최종 응답에는 등록한 댓글 수와 링크를 짧게 남긴다.
